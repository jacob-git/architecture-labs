# AEG × SHIELD Lab #001 — Governed Self-Healing Feedback

## Research question

Can runtime incident evidence generated by a protection layer change a later governance decision for the same class of proposed change?

## Hypothesis

A governance boundary that evaluates only pre-execution intent can miss failures visible only after execution. If SHIELD converts runtime degradation into bounded incident evidence and AEG consumes that evidence as an explicit risk input, a proposal class initially allowed should be denied or escalated after a severe runtime failure.

This lab tests that feedback mechanism. It does not claim autonomous systems can safely learn arbitrary policies from production behavior.

## Loop under test

`Intent → AEG govern → Execute → SHIELD observe → Protect → Evidence → AEG govern again`

Responsibilities stay separate:

- **AEG** decides whether a proposal may execute from declared proposal risk plus recorded evidence for its change class.
- **SHIELD** does not grant authority. It observes runtime behavior and chooses `none`, `contain`, or `rollback` when guardrails are crossed.
- **EvidenceMemory** is the narrow handoff boundary. SHIELD incidents add an explicit penalty to a change class; AEG may use that penalty on later evaluation.

## Fixed scenarios

| Scenario | Initial AEG decision | Runtime behavior | SHIELD action | Re-evaluation |
|---|---|---|---|---|
| `safe_change` | allow | inside guardrails | none | allow |
| `latent_failure` | allow | error rate and latency breach | rollback | deny |
| `policy_violation` | allow | runtime policy violation | rollback | deny |

A fourth unit test preloads prior incident evidence and verifies AEG can deny a matching proposal before execution.

## Reproduce

Python 3.11+; standard library only.

```bash
python -m unittest tests.test_aeg_shield_001
python -m labs.aeg_shield_001.runner
```

Expected runner property:

```json
"learning_demonstrated": true
```

In the deterministic `latent_failure` scenario, the proposal begins at risk `0.35`, below the AEG threshold of `0.70`. SHIELD observes error-rate and latency breaches, rolls back, and emits severity `0.45`. Re-evaluation sees effective risk `0.80` and denies the proposal.

## What this result means

The lab demonstrates one narrow architectural claim: **post-execution evidence can materially change a later pre-execution governance decision without merging governance and runtime-protection responsibilities.**

The failure was not visible to AEG at proposal time. The feedback path preserves the distinction between deciding whether an action is authorized and deciding whether an executing system remains healthy.

## Limitations

- The numeric risk model is not calibrated for production use.
- Severity values are fixed experimental constants, not learned probabilities.
- The harness has no real LLM, network, service mesh, deployment system, or distributed telemetry.
- Evidence is keyed only by `change_type`; real systems need provenance, scope, freshness, correlation, authority, and decay controls.
- A runtime incident should not automatically become permanent policy. Human review, expiry, counter-evidence, and environment boundaries are future work.
- The experiment demonstrates feedback mechanics, not universal safety or self-healing.

## Next falsification stages

1. Inject stale or unrelated incident evidence and measure wrongful denials.
2. Ensure correlated symptoms from one root cause do not accumulate unlimited penalty.
3. Test whether successful repeated executions can safely reduce a learned penalty.
4. Prove an incident in one environment cannot silently poison governance in another.
5. Add a real-model proposal stage while keeping AEG and SHIELD deterministic and independently inspectable.

The next stages are intended to break the feedback loop, not merely strengthen the first result.
