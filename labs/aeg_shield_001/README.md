# AEG × SHIELD Lab #001 — Governed Self-Healing Feedback

## Research question

Can runtime incident evidence generated by a protection layer change a later governance decision for the same class of proposed change without allowing stale, correlated, cross-environment, or untrusted evidence to poison governance?

## Phase A — feedback mechanism

Phase A established the narrow positive result.

`Intent → AEG govern → Execute → SHIELD observe → Protect → Evidence → AEG govern again`

Responsibilities stay separate:

- **AEG** decides whether a proposal may execute from declared proposal risk plus recorded evidence for its change class.
- **SHIELD** does not grant authority. It observes runtime behavior and chooses `none`, `contain`, or `rollback` when guardrails are crossed.
- **EvidenceMemory** is the handoff boundary. SHIELD incidents add an explicit penalty to a change class; AEG may use that penalty on later evaluation.

### Fixed Phase A scenarios

| Scenario | Initial AEG decision | Runtime behavior | SHIELD action | Re-evaluation |
|---|---|---|---|---|
| `safe_change` | allow | inside guardrails | none | allow |
| `latent_failure` | allow | error rate and latency breach | rollback | deny |
| `policy_violation` | allow | runtime policy violation | rollback | deny |

A fourth unit test preloads prior incident evidence and verifies AEG can deny a matching proposal before execution.

The deterministic `latent_failure` scenario begins at risk `0.35`, below the AEG threshold of `0.70`. SHIELD observes error-rate and latency breaches, rolls back, and emits severity `0.45`. Re-evaluation sees effective risk `0.80` and denies the proposal.

**Phase A conclusion:** post-execution evidence can materially change a later pre-execution governance decision without merging governance and runtime-protection responsibilities.

## Phase B — adversarial feedback integrity

Phase B attacks the v1 feedback-memory boundary rather than extending the happy path.

The frozen adversarial suite asks whether evidence that should be ignored, isolated, deduplicated, or rejected can still change AEG decisions.

| Check | Required behavior | feedback-memory-v1 | Result |
|---|---|---|---|
| `stale_evidence` | old incident evidence should expire or decay | old penalty remains permanent | **fail** |
| `correlated_incidents` | symptoms from one root cause should not count independently | penalties accumulate | **fail** |
| `environment_contamination` | production evidence should not silently govern staging | memory has no environment boundary | **fail** |
| `poisoned_feedback` | untrusted evidence must not change governance state | memory accepts evidence without authority or provenance | **fail** |

### Phase B result

**feedback-memory-v1 passes 0 of 4 adversarial integrity checks.**

In all four frozen counterexamples the expected governance outcome is `allow`, because the supplied evidence is stale, duplicated by a shared cause, scoped to another environment, or untrusted. The v1 memory instead applies the penalty and returns `deny`.

This is a useful negative result. The Phase A feedback mechanism works, but the evidence handoff is not yet a safe governance input.

## What Phase B changes

The next memory revision must make evidence a governed artifact rather than a bare numeric penalty. At minimum the evidence contract now needs:

1. **freshness** — observed-at time, expiry, and/or explicit decay;
2. **scope** — environment and other relevant operational boundaries;
3. **correlation identity** — enough causal identity to prevent one incident from masquerading as multiple independent incidents;
4. **provenance and authority** — producer identity and a rule for which producers are trusted to influence governance;
5. **bounded aggregation** — an explicit policy for how accepted evidence accumulates.

Those requirements are derived from counterexamples, not added speculatively.

## Limitations

- The numeric risk model is not calibrated for production use.
- Severity values are fixed experimental constants, not learned probabilities.
- The harness has no real LLM, network, service mesh, deployment system, or distributed telemetry.
- The Phase B scenarios are deterministic falsification cases, not an independent production benchmark.
- Correctly rejecting bad evidence does not prove that accepted evidence is causally correct.
- The experiment demonstrates feedback mechanics and feedback-integrity failure modes, not universal safety or autonomous self-healing.

## Next falsification stage

Build **feedback-memory-v2** from the four Phase B failures, then run the Phase A suite and the unchanged Phase B adversarial suite against it. The repair should not be considered successful unless it preserves the original learning behavior while rejecting stale, correlated, cross-environment, and untrusted evidence.
